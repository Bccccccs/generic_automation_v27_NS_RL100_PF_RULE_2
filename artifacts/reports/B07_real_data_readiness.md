# B07 真实数据成熟度判断

## 结论

当前真实 STAR 数据还不能用于真实 ROM 训练。

原因不是程序读不了数据。现在 `G00_nojet_existing` 和 `G01_JET01_existing` 都能整理成标准 `processed/timeseries.csv`，每个 case 有 30000 行、`dt = 1e-4 s`、总时长约 3.0 s，并包含六个区域升力、`Fz_Total`、`Drag_Total`、`Pitch_Moment`、`Roll_Moment`、`Jet_Reaction_Z`、`JET_01..JET_24` 和 `cmd_massflow_01..24`。真正阻塞 ROM 训练的是数据内容还不够：只有一个真实单喷气区域、只有常值 step、没有喷前/关断恢复段、缺少 `actual_massflow_01..24`，并且基准波动与单喷气差分同量级。

## 当前可以用于什么

- 接口测试：可以。真实 STAR 导出已经能被读取、列名映射、合并 schedule，并生成标准 case 目录。可用于回归测试“真实文件能进管线”，但测试断言应关注 schema、行数、时间单调、列存在和质量报告，不应断言控制效果。
- 趋势分析：有限可以。`G01_JET01_existing - G00_nojet_existing` 显示 JET_01 对 S1 区域有可观察差分，其中区域平均变化最大的是 `Fz_S1R`，平均约 `+1215 N`。但这是跨 case 同时刻差分，不能替代同一 case 喷前基准或重复样本统计。
- 单喷气响应观察：仅限 JET_01 常值开启观察。可以看哪个区域可能最敏感、峰值量级和大致时间，但不能稳健估计动态延迟、恢复时间、非线性或喷口间耦合。
- 真实 ROM 训练：不可以。训练 ROM 至少需要多个喷气区、多个激励方式或幅值、可验证实际质量流量、重复基线和足够覆盖输入空间；当前只有一个 JET_01 常值 case，训练会把单个工况和数值漂移误当成动力学。

## JET_01 响应摘要

采用 `G01_JET01_existing` 减 `G00_nojet_existing`，按样本序号/物理时间对齐：

| 指标 | 当前结果 |
| --- | ---: |
| 指令质量流量 | `2.57 kg/s` |
| 实际质量流量 | 缺失，未用指令值替代 |
| 最大区域响应 | `Fz_S1R` |
| `Fz_S1R` 峰值变化 | `+4576.688 N` at `0.0112 s` |
| `Fz_S1R` 平均变化 | `+1215.003 N` |
| 估计延迟 | `0.0081 s`，低置信 |

延迟低置信的原因：JET_01 从第一个样本就开启，没有同一 case 的喷前窗口；只能用跨 case 差分和阈值估计。

## 第二周 ARX 使用边界

第二周 ARX 只能作为 Mock 回归测试。Mock 上的高准确率不能说明真实喷气控制有效，也不能作为真实 ROM 训练成熟的证据。

为避免真实仿真和 Mock 混用污染结论：

- Mock ARX 训练/验证指标只评价代码链路和递推实现。
- 真实 STAR 数据当前只进入读取、质量检查、趋势摘要和单喷气观察报告。
- `cmd_massflow_*` 不得复制成 `actual_massflow_*`。
- 任何使用真实 case 的 ARX 验证结果只能标记为接口/冒烟测试，不能写成物理预测准确率。
