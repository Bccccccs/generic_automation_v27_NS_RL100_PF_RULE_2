## 2. 各方向展开

### A. 在现有数据上做非线性诊断（立即可做）

- **做什么：** 给 ARX 加二次项和输入交叉项（`u_i·u_j`），其余设置不变，比较验证集滚动 RMSE 与底噪。
- **判据：** 验证误差若降到明显低于线性版本（相对底噪），说明存在可辨识的非线性；若没有变化，
  说明现有数据里看不出非线性，应把精力放在补数据上，不要上 MLP。
- **局限：** 数据里只有单喷口、两档幅值，交叉项实际上无法由数据辨识；这一步主要检验"幅值非线性"。

### B. 补充激励（B05 已规划）

- **内容：** `B6_T1_multilevel`（4 档流量）、`B6_T2_multiwidth`（3 种脉宽）、`B6_T3_pairs`（双喷口同时喷）、
  `B6_V1_mixed`（独立验证）。见 `artifacts/B05_next_CFD_case_plan.csv`。
- **要检验：** ① 幅值线性（4 档比 2 档可靠）；② 不同脉宽下同一模型是否预测得住；
  ③ 叠加：Δ(A+B) 与 Δ(A)+Δ(B) 的差是否在底噪内；④ 峰值比中位数是否 ≥ 0.95。
- **待定项：** 首个脉冲时刻。0.5 s 的事件已进入 B53 数据集并参与拟合，只是被 B54 逐事件诊断跳过
  （事件前基准落在滚动初始化段，`pre[0] < max_lag`，max_lag = 200 步）。要让首个事件也可评价，
  需要先核对片段起点再定时刻，不要沿用未经验证的 "≥ 0.6 s"。
- **代码准备：** 多脉宽、双喷口同时开启需要新增或扩展动作生成模式；双喷口事件要在逐喷口诊断中单独统计。

### C. 喷气量随时间连续变化的激励

- **动机：** 目前所有训练和验证事件都是"恒定流量的开关脉冲"（0.1 s，1.43 或 2.86 kg/s）。
  实际控制器给出的是连续变化的质量流量 ṁ(t)。需要知道 ROM 对任意 ṁ(t) 是否仍然有效。
  线性时不变系统由脉冲响应（或频率响应）完全决定，任意 ṁ(t) 的响应是它与脉冲响应的卷积；
  非线性则表现为：增益随幅值或变化速率而变、出现谐波/互调、喷气变化接近流场固有振荡时被放大（锁频）。
- **ṁ(t) 的几种形式（各自检验不同的东西）：**
  1. **多水平阶跃/随机多水平序列（PRBS 类）：** 流量在若干档之间随机切换，持续激励所有频率，是辨识的标准做法；
  2. **斜坡（不同变化速率）：** 检验响应是否取决于 dṁ/dt；
  3. **带偏置的正弦（ṁ = ṁ0 + a·sin 2πft）：** ṁ 不能为负，所以实际是"均值 + 振荡"；
     固定均值，用两档以上振幅 a、多个频率 f，检验幅值依赖和谐波；
  4. **扫频（chirp）：** 一次覆盖一段频带，用来估频率响应和相干函数。
- **要看的指标：** 相干函数（输入输出线性相关程度）、同一频率下两档幅值的增益是否一致、有无谐波，
  以及用脉冲数据辨识出的模型预测这些波形时，滚动误差相对底噪是否仍在同一量级。
- **现有生成器能做什么、不能做什么（已读代码）：**
  `chirp_keyjets`（`flow_control/excitation_patterns/chirp.py`）和 `prbs_demo` 是演示配置，
  不能直接用于正式算例：示例流量 0.02 kg/s（远低于我们的 1.43–2.86 kg/s）；
  chirp 对选定的**多个喷口施加同一波形**（不是单喷口）；波形按"窗口"取值，
  示例窗口 0.05 s 即波形采样率只有 20 Hz；示例频段 1–8 Hz。
  做正式实验需要：单喷口、流量与我们的安全范围一致、窗口取到求解步或接近求解步。
- **STAR 侧未验证的点：** 动作表每行可以给每个喷口不同的 `cmd_massflow`，原则上任意 ṁ(t) 可表达。
  但运行器把连续相同的行合并成一个窗口，ṁ(t) 连续变化时几乎每步都是一个窗口，
  宏的逐窗口开销、总耗时是否可接受**未测**，需要先跑一个很短的探针算例。
- **采样与频率范围：** ARX 有效步长 1 ms（奈奎斯特 500 Hz）；现有 0.1 s 脉冲的能量主要在二十赫兹以内，
  更高频需要更快变化的 ṁ(t)。
- **前置：** 先测基流的功率谱，确认基流主频；变化频段要覆盖并避开它们，分别看。
- **与线性假设的关系：** 因为 ṁ ≥ 0，带偏置的 ṁ(t) 是在"非零平均流量"附近的小信号响应；
  它和"从 0 起跳的脉冲"不是同一个工作点，需要单独检验线性模型在偏置工作点是否仍适用。

### D. 噪声与确定性的量化

- **GPU 上逐点相减的前提必须验证。** 旧 CPU 算例喷气前与参考逐点完全一致；GPU 求解可能不是逐位可复现的。
  检查训练、验证与 11 s 无喷气参考在 0–0.5 s 是否逐点一致。若不一致，逐点相减要改用统计基线。
- **重复运行：** 对同一动作表用不同初始扰动或重复一次，估计残差底噪，
  并与"喷气前差值噪声"的估计对照，判断底噪是否被高估或低估。
- **重复事件平均：** 同一"喷口 × 流量档"的事件数增加后，可用事件平均把不可预测残差压下去，
  降低辨识误差；这也是 B 方向要提高事件数的原因之一。

### E. 扩展喷口（暂缓，先探测）

- **现状：** 6 个代表喷口中，同段左右两个喷口的持续效果几乎相同，稳态增益矩阵条件数约 578，
  只提供 2–3 个独立控制方向。
- **做什么：** 先跑 `B6_P1_outer_probe`（J01/J04/J18/J20/J10/J12 单脉冲，约 5.4 s），
  看外侧喷口能否提供新的左右差异或 S3 持续响应，再决定进入 12 喷口。
- **成本提示：** 扩展直接成倍增加 CFD 成本；若新增喷口与现有喷口效果重合，不会提高可控性。

### F. 结构化非线性模型（条件触发）

按由简到繁的顺序，只有 A、B 的诊断显示非线性可辨识时才升级：

1. ARX + 二次项/交叉项（线性回归，参数可读）。
2. Hammerstein / Wiener：输入端或输出端的静态非线性 + 线性动力学。
3. 二阶 Volterra。
4. NARX（多项式或小 MLP）；LSTM 等序列网络放最后。

- **MLP 的使用条件：** 事件数要远多于现在的 24/12；要接受外推不可控、可解释性差；
  不能用它去拟合湍流残差——残差本来就预测不了。
- **可解释性要求：** 任务要求回答"哪个喷口影响哪个区域、方向、延迟、恢复、传播"，
  线性模型可直接读出，非线性模型需要额外做灵敏度分析。

### G. 面向控制

- **残差当扰动：** ROM 只预测平均响应，湍流分岔残差要作为不可预测扰动处理，控制器必须对其鲁棒。
- **控制能力的结构限制：** 响应按"本区 → 同段对侧 → 相邻上游段"转移，S3 没有下游喷口，持续控制能力弱；
  要抬升某一段，应使用其**后面一段**的喷口。
- **先决条件：** B 方向完成后，ROM 在叠加、幅值、脉宽上得到验证；
  再决定是模型预测控制（MPC）还是强化学习。是否直接用 ROM 作训练环境，取决于其外推边界。

### H. 数值与物理可信度（贯穿）

- **GPU 状态：** 当前三次真实运行（11 s 参考、训练、验证）的 `gpu_execution.json` 都是
  `GPU_EXECUTION_UNCONFIRMED`（日志解析器不认识该 STAR 构建），数据本身完整，
  但"实际用了 GPU"没有软件证据；需要 `hy-smi` 利用率等旁证。
- **时间步敏感性：** 仓库里有 `temp_no_jet_probe_dt5e-5.yaml`，是否已做过时间步对比未确认；
  结论依赖 dt = 1e-4 时需要补一个 dt 敏感性检查。
- **力的定义：** `Jet_Reaction_Z` 在无喷气基准里非零，是 J 表面压力加剪切力，
  不是喷气动量反作用力；动量项没有记录。目前用相对无喷气参考的差值处理，
  B04 质量门禁仍会因此判 FAIL，需要后续修改判据或字段名。
- **区域名：** `AGENTS.md` 写 `--region 区域`，B52 v2 实际使用 `减运算`且结果正常，
  下一批算例启动前需要确认。
- **算例成本：** B05 的 5 个算例合计约 46 物理秒，按上面的速度约 11 天单节点 GPU 时间；
  单个 10.5 s 算例约 61 h，接近 3 天的 Slurm 时限，需要预留余量。

## 3. 建议的推进顺序

1. **A、D 并行（不需要新算例）：** 加二次项和交叉项的诊断；检查 0–0.5 s 逐点一致性。
2. **定首个脉冲时刻，补动作生成模式：** 多脉宽、双喷口同步脉冲；确认区域名。
3. **跑 B05 的 T1/T2/T3 与 V1，同时跑 P1 探测。**
4. **根据结果决定：** 线性够用 → 进入 G；叠加或频率相关性明显 → 走 F；
   外侧喷口提供新方向 → 再评估 E。
5. **C（喷气量连续变化）在 B 的结果出来后加入，** 先跑一个很短的探针算例确认 STAR 逐步变流量的运行开销，
   再用两档幅值的随机多水平序列和带偏置正弦判断线性时不变是否成立。
