# B02 喷气激励信号说明

本阶段交付的是 CFD 实验输入表生成工具，不是控制器，也不判断哪个喷气区最好。
生成出来的 `actuation_schedule.csv` 用来告诉 STAR-CCM+ 在每一个物理时间窗口里，
24 个喷气区分别是打开还是关闭，以及每个喷气区的指令质量流量是多少。

所有输出表统一使用以下列：

```text
time, window_id, t_start, t_end,
JET_01 ... JET_24,
cmd_massflow_01 ... cmd_massflow_24
```

其中 `time`、`t_start`、`t_end` 都是秒，不是 STAR-CCM+ 的求解器迭代步。
`JET_01...JET_24` 是 0/1 开关列；`cmd_massflow_01...cmd_massflow_24` 是质量流量命令。
如果某个 `JET_xx = 0`，对应的 `cmd_massflow_xx` 必须为 0；如果 `JET_xx = 1`，
对应质量流量必须大于 0。

## 1. 无喷气参考段

配置文件：

```text
configs/actions/no_jet_reference.yaml
```

输出目录：

```text
runs/schedule_examples/no_jet_reference/
```

这个信号让 24 个喷气区在整段时间里全部关闭。它的作用是建立无喷气基准，
后续可以把有喷气工况下的升力、阻力、压力分布和这个基准进行比较。

## 2. 单喷气区脉冲

配置文件：

```text
configs/actions/pulse_singlejet.yaml
```

输出目录：

```text
runs/schedule_examples/pulse_singlejet/
```

这个信号让一个喷气区短时间打开，然后马上关闭。当前例子是 `JET_03`
在 `0.10-0.20 s` 打开。它适合观察单个喷气区对 6 个载荷单元的瞬时影响、
响应延迟和下游传播。

## 3. 单喷气区阶跃

配置文件：

```text
configs/actions/step_singlejet.yaml
```

输出目录：

```text
runs/schedule_examples/step_singlejet/
```

这个信号让一个喷气区从某个时间开始持续打开一段时间。当前例子是 `JET_03`
从 `0.10 s` 打开并保持到 `0.80 s`。它适合观察持续喷气对平均升力、
阻力和压力分布的影响。

## 4. 关键喷气区扫频

配置文件：

```text
configs/actions/chirp_keyjets.yaml
```

输出目录：

```text
runs/schedule_examples/chirp_keyjets/
```

这个信号先选少数关键喷气区，然后让喷气强度按周期变化，并且频率逐渐升高。
当前例子使用 `JET_03, JET_07, JET_14, JET_18`。这不是为了本周直接给出物理结论，
而是为了给后续频带选择提供输入数据，看车底流场是否对某些喷气频率更敏感。
喷气区编号后续需要和浩坤确认。

## 5. PRBS 伪随机开关

配置文件：

```text
configs/actions/prbs_demo.yaml
```

输出目录：

```text
runs/schedule_examples/prbs_demo/
```

PRBS 看起来像随机开关，但由 `random_seed` 固定，因此同一个种子会生成完全相同的表，
换一个种子会生成不同的表。这个信号比简单脉冲或阶跃包含更多输入组合，
适合给后续 ROM 或动态模型辨识提供更丰富的数据。

当前配置限制最多同时开启 4 个喷气区，总质量流量不超过 `0.08`。

## 6. 稀疏随机分组

配置文件：

```text
configs/actions/pilot_sparse24.yaml
```

输出目录：

```text
runs/schedule_examples/sparse24/
```

这个信号延续第一周的 24 喷气区随机分组任务。它用 72 个主激励窗口和 8 个无喷气参考窗口，
在较少窗口里公平测试 24 个喷气区和少量组合的影响。每个主激励窗口恰好开启 3 个喷气区，
每个喷气区在 72 个主激励窗口中恰好出现 9 次，同一 3 喷气区组合不重复，
同一喷气区不允许连续开启超过 2 个窗口。

## 运行命令

从项目根目录运行：

```bash
.venv/bin/python -m flow_control.generator.schedule_generator --config configs/actions/pulse_singlejet.yaml --output-dir runs/pulse_singlejet
```

替换 `--config` 后面的文件名即可生成其他模式。生成后可以检查：

```bash
.venv/bin/python -m pytest -q tests/test_actuation_schedule_generator.py
```

也可以直接打开对应目录下的：

```text
actuation_schedule.csv
actuation_heatmap.svg
total_mass_flow.csv
total_mass_flow_curve.svg
config_summary.yaml
validation_report.json
```
