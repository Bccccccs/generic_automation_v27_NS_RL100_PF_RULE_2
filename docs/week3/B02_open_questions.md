## 1. 当前已经暴露的疑问

### 1.1 无喷气时 `Jet_Reaction_Z` 为什么不是零？

当前无喷气样例中 `Jet_Reaction_Z` 出现非零值，最大绝对值约 `2.97e3 N`。从字段名看，它像是喷气反作用力；但无喷气工况下理论上不应有喷气直接反作用力。

现在的疑问是：`Jet_Reaction_Z` 到底是不是纯喷气反作用力？它是否包含其他边界力、参考力、残余力或 STAR monitor 定义中的非喷气贡献？如果它不是纯喷气反作用力，那么后续不能直接把它当作喷气直接力来解释。

当前已确认：`Jet_Reaction_Z` report 的单位为 `N`，坐标系为 `Laboratory`，方向为 `[0.0, 0.0, 1.0]`，力选项为“压力 + 剪切”，参考压力为 `0.0 Pa`。它选中了全部 `J01..J24` 喷气口，没有选中 `JET01..JET24` 底部边界。当前 `.sim` 中 `J01` 的 Region Boundary 类型显示为“壁面”，建模人已确认最终喷气建模方式是把 `J01..J24` 这些喷气口边界改成质量流量入口。因此当前 wall 状态应理解为尚未切换到最终喷气边界条件的状态；`Jet_Reaction_Z` 在 wall 状态下更准确地说是喷气口壁面上的 +Z 压力+剪切力 report，无喷气时非零可以由这些壁面上仍存在压力/剪切贡献解释。

### 1.2 无喷气和 `JET_01` 升力反常首先出现在哪里？

浩坤已经指出无喷气和 `JET_01` 的升力数据存在反常，但当前还没有明确反常首先出现在哪个量、哪个时刻、哪个区域。

### 2.8 STAR 输出时间与动作窗口如何对应？

当前动作表窗口类似 `0.0-0.0001, ..., 2.9999-3.0 s`，STAR monitor 输出时间类似 `0.0001, 0.0002, ..., ~3.0 s`。也就是说，输出样本落在动作窗口终点上。

当前已确认当前命令行宏的归属规则：宏先写入 row i 的质量流量，再把 STAR 从 `t_start` 推进到 `t_end`，然后在 `t_end` 采样 report。因此 `t_end` 样本属于刚结束的 row i，标准对齐规则为 `t_start < t_sample <= t_end`。仍需注意：如果后续改用 STAR GUI 的表（时间）profile 或其他宏，必须重新确认边界归属，不能直接套用当前 CLI 宏规则。

## 3. B35 升力反常诊断疑问

### 3.1 喷气开启时刻应该如何定义？

B35 要求以喷气开启时刻为 `t=0` 对齐 no-jet 和 `JET_01`。这里不能把单行动作窗口直接叫喷气窗口：动作窗口是 `actuation_schedule.csv` 的最小离散行，喷气窗口是某个喷口连续开启的一整段物理时间。

当前标准定义：先把 `JET_XX == 1` 且 `cmd_massflow_XX != 0` 的连续动作窗口合并为喷气窗口，再把该喷气窗口的 `t_start` 作为命令喷气开启时刻。当前 `G01_JET01_existing` 中 `JET_01` 从 row 0 到 row 29999 都开启，`cmd_massflow_01=2.57 kg/s`，所以命令喷气窗口为 `0.0-3.0 s`，命令喷气开启时刻为 `0.0 s`。

仍需确认的是：`actual_massflow_01` 的真实回读是否也从 `0.0 s` 开始非零，以及力曲线首次响应是否因物理/数值滞后晚于命令喷气开启时刻。命令开启、实际质量流量开启和力响应开启不能混为一个概念。

### 3.2 喷气前基准段应该取哪里？

B35 明确要求先计算喷气前基准段的平均值和波动范围，再计算喷气后相对基准的变化。当前还没有确定基准段时间窗口。

现在的疑问是：no-jet 和 `JET_01` 各自的喷气前基准段是哪一段？是否需要排除 case 开始后的初始过渡段？如果基准段取错，喷气后的相对变化会被初始漂移或未稳定状态污染。

当前已确认：单喷气 case 没有喷气前基准阶段。因此 B35 不能在同一个 `JET_01` case 内计算“喷气前均值 -> 喷气后变化”。当前可用基准只能是 no-jet case 的同时间窗口基准；报告中必须明确这是跨 case 基准，而不是同 case 喷气前基准。

### 3.3 喷气后比较窗口应该取哪里？

喷气后响应可能包含开启瞬态、准稳态段和后续漂移。不同窗口对应的平均变化、峰值变化和波动范围可能不同。

现在的疑问是：B35 应该用哪一段作为喷气后比较窗口？是否需要把喷气刚开启的瞬态和后续平均段分开？如果比较窗口不明确，就不能判断异常发生时刻和持续性。

### 3.4 两个 case 是否仍在漂移？

如果 no-jet 自身仍在漂移，`JET_01` 相对 no-jet 的变化不能只扣一个固定基准平均值。

现在的疑问是：no-jet 和 `JET_01` 在比较窗口内是否仍存在趋势性漂移？漂移幅度是否已经和喷气引起的变化同量级？如果仍在漂移，异常可能来自数值未稳定，而不是喷气本身。

### 3.5 6 区升力之和与 `Fz_Total` 是什么关系？

6 个区域力之和不一定等于整车总力。它们可能只覆盖局部表面，也可能与整车总力存在重叠或遗漏。

现在的疑问是：`Fz_S1L + Fz_S1R + Fz_S2L + Fz_S2R + Fz_S3L + Fz_S3R` 是否应该与 `Fz_Total` 近似一致？如果不一致，差异来自未覆盖表面、重复积分、方向不同，还是定义本来就不同？这个问题会影响区域异常和整车异常之间的关系判断。

当前已确认：6 个区域力和 `Fz` 在单位、坐标系、方向和力选项上一致，都是 `N`、`Laboratory`、`[0.0, 0.0, 1.0]`、压力+剪切。6 个区域力覆盖并互斥划分 `JET01..JET24` 底部边界；建模人已确认 `Fz` 实际不包含 `tail`。但当前数据中 `Fz_Total` 与 6 区底部力之和仍相差很大，因此二者不能简单视为同一底部区域力的两种写法。这个差异需要继续由积分面、report 定义或导出映射解释。

### 3.6 喷气面力是否被重复计入？

B35 需要区分车体气动力、喷气直接反作用力和合成有效力。但如果喷气面力已经包含在 `Fz_Total` 或某些区域力里，再额外加 `Jet_Reaction_Z` 就会重复计入。

现在的疑问是：`Fz_Total` 是否包含喷气边界？6 个区域力是否包含喷气面？`Jet_Reaction_Z` 和 `Fz_Total` 是否存在重叠积分表面？如果这些边界关系不清楚，有效总力的计算就可能反号、漏算或重复计算。

当前已确认：`Fz` 选中 `JET01..JET24` 底部边界，`Jet_Reaction_Z` 选中全部 `J01..J24` 喷气口，二者积分面不重叠。建模人已确认 `Fz` 不包含 `tail`。因此此前担心的 `Fz + Jet_Reaction_Z` 重复计入同一批 `JET` 底部边界的问题可以解除；但 `Fz_Total` 与 6 区底部力之和仍存在明显数值差异，需要继续核对 `Fz` 与 6 区 report 的积分面/导出映射。

### 3.7 有效总力应该如何理解？

B35 要区分车体气动力变化、喷气直接反作用力和两者合成后的有效变化。但在符号和积分面未确认前，有效总力的公式还不确定。

现在的疑问是：有效总力到底应该理解为 `Fz_Total + Jet_Reaction_Z`，还是 `Fz_Total - Jet_Reaction_Z`，或者只看某个已经包含喷气边界的总力？如果公式不清楚，“喷气是否改善升力”的判断可能完全相反。

当前已确认：`Fz` 与 `Jet_Reaction_Z` 的积分面不重叠，可以把 `Fz_Total + Jet_Reaction_Z` 作为当前 STAR report 覆盖表面的合计 +Z 力候选量。但这个候选量的准确名称应是“`JET01..JET24` 底部边界 + `J01..J24` 喷气口壁面的 Laboratory +Z 压力+剪切力合计”，不是严格整车升力。是否把它作为 B35 的有效总力，还需要确认 `J01..J24` 改成质量流量入口后的力方向和质量流量正负号。

### 3.8 `actual_massflow_01` 的方向和大小是否正确？

`cmd_massflow_01 = 2.57 kg/s` 是动作表指令值，`actual_massflow_01` 才能证明 STAR 中实际发生的质量流量。当前已看到 `J01` 是质量流量入口，质量流率方法为常数，值为 `2.57 kg/s`；但当前没有实际喷气质量流量监测 report/monitor。

当前已确认：现有 STAR 模板没有 `actual_massflow_01` 回读监测。因此 B35 中“实际质量流量”不能由真实 monitor 曲线验证，只能记录为“边界条件设定值为 `2.57 kg/s`，缺少 actual_massflow 独立监测证据”。质量流量入口正值 `2.57 kg/s` 已确认表示喷入计算域。

### 3.9 喷气反作用力符号是否与质量流量方向一致？

喷气反作用力应该能和喷口法向、质量流量方向形成一致解释。但当前 `Jet_Reaction_Z` 的符号定义和 `actual_massflow_01` 的正负号关系还没确认。

现在的疑问是：当 `actual_massflow_01` 表示喷气开启时，`Jet_Reaction_Z` 应该变为正还是负？这个变化是否符合喷口法向和车体受力方向？如果不一致，可能是 report 定义反号，也可能是统计对象不是车体受力。

### 3.10 如果口径问题都排除，是否可能是真实流场响应？

B35 不能强行给出唯一原因，但需要区分数据定义问题、数值过程问题和可能的真实物理响应。

现在的疑问是：如果力方向、喷气面重复计入、`actual_massflow` 方向和大小、`Jet_Reaction_Z` 符号、checkpoint、数据窗口和漂移都不能解释异常，那么是否存在真实物理机制，例如喷气破坏原有高压区、增强泄漏、产生卷吸、改变底部流动分离或压力恢复？当前缺少流场证据，因此这类解释只能作为待判断的物理可能性。
