# B32 / B35 当前疑问清单

本文件只整理当前仍有疑问、需要进一步确认的信息。这里不写处理建议，只说明问题是什么，以及为什么现在还不能从代码、CSV header、文件名或已有图表中确定。

## 1. 当前已经暴露的疑问

### 1.1 无喷气时 `Jet_Reaction_Z` 为什么不是零？

当前无喷气样例中 `Jet_Reaction_Z` 出现非零值，最大绝对值约 `2.97e3 N`。从字段名看，它像是喷气反作用力；但无喷气工况下理论上不应有喷气直接反作用力。

现在的疑问是：`Jet_Reaction_Z` 到底是不是纯喷气反作用力？它是否包含其他边界力、参考力、残余力或 STAR monitor 定义中的非喷气贡献？如果它不是纯喷气反作用力，那么后续不能直接把它当作喷气直接力来解释。

当前已确认：`Jet_Reaction_Z` report 的单位为 `N`，坐标系为 `Laboratory`，方向为 `[0.0, 0.0, 1.0]`，力选项为“压力 + 剪切”，参考压力为 `0.0 Pa`。它选中了全部 `J01..J24` 喷气口，没有选中 `JET01..JET24` 底部边界。当前 `.sim` 中 `J01` 的 Region Boundary 类型显示为“壁面”，建模人已确认最终喷气建模方式是把 `J01..J24` 这些喷气口边界改成质量流量入口。因此当前 wall 状态应理解为尚未切换到最终喷气边界条件的状态；`Jet_Reaction_Z` 在 wall 状态下更准确地说是喷气口壁面上的 +Z 压力+剪切力 report，无喷气时非零可以由这些壁面上仍存在压力/剪切贡献解释。

### 1.2 无喷气和 `JET_01` 升力反常首先出现在哪里？

浩坤已经指出无喷气和 `JET_01` 的升力数据存在反常，但当前还没有明确反常首先出现在哪个量、哪个时刻、哪个区域。

现在的疑问是：异常是先出现在 6 个区域力中的某一区，例如 `Fz_S1L/S1R/S2L/S2R/S3L/S3R`，还是先出现在 6 区升力之和、`Fz_Total`、`Jet_Reaction_Z`、`actual_massflow_01`，或者车体气动力与喷气反作用力合成后的有效总力中？如果最早异常量不清楚，就无法判断问题更像是区域载荷定义问题、整车力定义问题、喷气输入问题，还是物理响应问题。

### 1.3 CSV 列名能否代表真实物理方向？

当前只能从 STAR 导出的 CSV header 看到 `Fz`、`Z`、`Reaction`、`Drag`、`Pitch`、`Roll` 等名称和单位。列名能说明数据来自哪个 monitor，但不能证明 STAR report 的方向向量、坐标系和积分表面。

现在的疑问是：`Fz_Total` 的正值是否一定代表项目语义中的升力增加？`Jet_Reaction_Z` 的正值是否一定代表喷气对车体的 Z 向反作用力？6 个区域力的正方向是否一致？这些都不能只靠列名判断。

当前已确认：`Fz`、`Jet_Reaction_Z` 和 6 个区域力 `S1L/S1R/S2L/S2R/S3L/S3R` 都是 `Laboratory` 坐标系下 `[0.0, 0.0, 1.0]` 方向的“压力 + 剪切”力，单位均为 `N`。因此这些 Z 向力 report 的正方向已经可以确定为 `Laboratory +Z`。仍未确认的是 `Drag_Total`、`Pitch_Moment`、`Roll_Moment` 的方向、坐标系、轴和力矩中心。

### 1.4 no-jet 和 `JET_01` 是否真的可直接对比？

当前两个 case 的数据行数、采样步长和总时长看起来一致，都是约 `30000` 行、`dt=0.0001 s`、总时长约 `3.0 s`。但这只能说明导出数据格式相似，不能证明两个 case 的计算起点和数值状态一致。

现在的疑问是：no-jet 和 `JET_01` 是否从同一个 checkpoint、同一个 `.sim`、同一套网格、同一套 solver 设置、同一初始流场继续计算？如果不是，升力差异可能来自初始状态或数值漂移，而不一定来自喷气。

## 2. B32 真实 STAR 数据接入疑问

### 2.1 24 个喷气区的真实边界是什么？

当前已确认 STAR 命名口径：`JET01..JET24` 是底部边界，`J01..J24` 是喷气口。因此算法侧 `JET_01..JET_24` 如果表示喷气开关和质量流量控制，真实控制对象应映射到 `J01..J24`，不能映射到 `JET01..JET24`。

当前建模人已确认：`J01..J24` 这些喷气口只要改成质量流量入口，就是最终喷气建模方式。现在仍需确认的是：每个 `JET_XX -> JXX` 是否存在编号错位、多个喷气口绑定或多面合并，以及质量流量入口的具体 profile、正负号和窗口切换规则。

### 2.2 每个喷气区的面积和法向是否明确？

喷气质量流量、喷气速度、喷气方向和反作用力方向都依赖喷气口面积和法向。当前已知 `J01..J24` 是对应区域喷气口，但这些喷气口的面积和法向不能从 `actuation_schedule.csv` 或 `timeseries.csv` 中看出来。

现在的疑问是：每个 `J01..J24` 喷气口面积是多少？面法向在哪个坐标系下定义？法向方向与 `actual_massflow` 正负号、`Jet_Reaction_Z` 正负号之间是什么关系？如果面积或法向不清楚，喷气反作用力大小和符号都无法可靠解释。

### 2.3 `JET_01` 是否是真正的单喷气？

B35 当前重点比较 no-jet 和算法侧 `JET_01`。但当前 STAR 命名里 `JET01` 是底部区域，`J01` 才是该区域喷气口。如果动作表里的 `JET_01` 实际控制的是 `J01` 喷气口，而 report 里的 `JET01` 统计的是底部区域，二者不能混为同一个边界。

当前已确认算法侧 `JET_01` 的几何喷气口候选对象应是 `J01`，不是底部边界 `JET01`。建模人已确认最终应把 `J01` 改成质量流量入口来实现喷气。因此现在的疑问收敛为：`cmd_massflow_01=2.57 kg/s` 在质量流量入口中的正负号、profile 绑定、时间窗口切换是否正确，以及是否可能存在边界映射错误，导致实际喷气位置不是预期的第 1 区喷气口。

### 2.4 6 个区域力的 report 定义是什么？

当前统一列名为 `Fz_S1L`、`Fz_S1R`、`Fz_S2L`、`Fz_S2R`、`Fz_S3L`、`Fz_S3R`。这些列名说明算法侧把它们当作 6 个区域力，但不能证明 STAR report 的真实积分面和方向。

现在的疑问是：这 6 个 report 分别积分了哪些表面？它们的 Direction Vector 和 Coordinate System 是否相同？正值是否都代表同一个物理方向？如果 6 个区域力定义不一致，后续比较哪个区域升力先异常就可能不可靠。

当前已确认：6 个区域力 report 的单位均为 `N`，坐标系均为 `Laboratory`，方向均为 `[0.0, 0.0, 1.0]`，力选项均为“压力 + 剪切”，参考压力均为 `0.0 Pa`。它们选中的是 `JET` 底部边界，不是 `J` 喷气口，并且形成 24 个底部边界的互斥分区：`S1L=JET01/JET02/JET05/JET06`，`S1R=JET03/JET04/JET07/JET08`，`S2L=JET09/JET10/JET13/JET14`，`S2R=JET11/JET12/JET15/JET16`，`S3L=JET17/JET18/JET21/JET22`，`S3R=JET19/JET20/JET23/JET24`。

### 2.5 `Fz_Total` 是否就是整车升力？

`Fz_Total` 来自 `Fz Monitor`，单位是 N，但这仍不能证明它就是项目语义上的整车升力。

现在的疑问是：`Fz_Total` 的 Direction Vector 是不是预期升力方向？它使用哪个坐标系？积分表面是否覆盖整车？是否包含喷气面？如果它不是严格的整车升力，B35 中“整车气动力变化”的含义就需要重新界定。

当前已确认：`Fz` report 的单位为 `N`，坐标系为 `Laboratory`，方向为 `[0.0, 0.0, 1.0]`，力选项为“压力 + 剪切”，参考压力为 `0.0 Pa`。其部件选择中包含全部 `JET01..JET24` 底部边界和一个 `tail`，没有选中 `J01..J24` 喷气口。因此 `Fz_Total` 更准确地说是“底部 24 区 + tail 的 STAR +Z 压力+剪切力”，不能在未确认整车其他外表面前直接叫严格整车升力。仍未确认的是 `tail` 的物理含义和 CSV 中统一列 `Fz_Total` 是否只对应这个 `Fz` report。

### 2.6 `Drag_Total`、`Pitch_Moment`、`Roll_Moment` 的正方向是什么？

阻力和力矩的正负号不能从列名推出。`Drag_Total` 可能按来流方向、反来流方向或 STAR 自定义方向输出；`Pitch_Moment` 和 `Roll_Moment` 还依赖力矩中心、坐标系和轴方向。

现在的疑问是：这些量的正值分别代表什么物理方向？力矩中心在哪里？如果这些定义不清楚，整车气动力变化中的阻力、俯仰和滚转只能画曲线，不能可靠解释正负变化。

### 2.7 `Jet_Reaction_Z` 的 report 究竟统计什么？

`Jet_Reaction_Z` 是当前最关键的疑问之一。名称显示它是喷气相关 Z 向反力，但它的实际含义必须由 STAR report 定义决定。

现在的疑问是：它统计的是喷口边界上的流体受力，还是喷气对车体的反作用力？它统计全部喷口边界还是只统计打开喷口？它是否包含关闭喷口、壁面、内部面或其他非喷气边界？无喷气时它是否应严格为零？这些问题直接决定它能不能用于有效总力合成。

当前已确认：`Jet_Reaction_Z` 的定义与 `Fz` 在单位、坐标系、方向、力选项和参考压力上相同，均为 `Laboratory +Z` 方向的“压力 + 剪切”力。其部件选择包含全部 `J01..J24` 喷气口，不包含 `JET01..JET24` 底部边界；截图中未看到 `background` 被选中。当前 `.sim` 中 `J01` 是 wall boundary；建模人已确认最终喷气建模需要把 `J01..J24` 改成质量流量入口。因此在 wall 状态下它更准确地说是喷气口壁面上的 +Z 压力+剪切力 report；在最终质量流量入口状态下，它可作为喷气口边界 +Z 力 report 使用，但仍需确认该 report 的符号是否按项目意图代表喷气反作用力。

### 2.8 STAR 输出时间与动作窗口如何对应？

当前动作表窗口类似 `0.0-0.0001, ..., 2.9999-3.0 s`，STAR monitor 输出时间类似 `0.0001, 0.0002, ..., ~3.0 s`。也就是说，输出样本落在动作窗口终点上。

现在的疑问是：`t_end` 时刻的 STAR 输出属于刚结束的动作窗口，还是已经切换到下一行动作之后的响应？动作表边界规则到底是 `[t_start, t_end)`、`(t_start, t_end]`，还是只能按当前 ingest 的同序号行对齐？如果这个问题不清楚，喷气开启时刻和力响应可能错一行。

### 2.9 采样间隔是否固定？

当前样例的采样间隔约为 `0.0001 s`，但后续正式算例是否都保持这个输出频率还不确定。

现在的疑问是：真实 STAR 数据后续是否始终使用 `dt=0.0001 s` 导出？如果不同 case 使用不同采样间隔或降采样，喷气开启瞬态、峰值时刻和波动范围的比较方式都会受到影响。

### 2.10 `.sim`、网格和 `runs/real_star/` 数据版本是否能追溯？

当前 `runs/real_star/` 已经加入 Git 跟踪，但 Git 只能记录仓库中的当前文件版本，不能自动说明这些文件来自浩坤哪一批原始 STAR 导出，也不能说明对应哪个 `.sim` 和网格。

现在的疑问是：当前真实 `.sim` 文件的 STAR 版本、sim 文件标识或哈希、网格版本是什么？`runs/real_star/` 对应的原始 realstar 数据版本、目录标识或哈希、来源路径、更新时间是什么？no-jet 和 `JET_01` 是否来自同一批 realstar 导出？如果版本追溯不清楚，后续诊断结论就难以复现。

## 3. B35 升力反常诊断疑问

### 3.1 喷气开启时刻应该如何定义？

B35 要求以喷气开启时刻为 `t=0` 对齐 no-jet 和 `JET_01`，但“喷气开启”有多个可能定义。

现在的疑问是：应该以动作表中 `JET_01` 由 0 变 1 为准，还是以 `cmd_massflow_01` 非零、`actual_massflow_01` 非零，或力曲线首次响应为准？不同定义可能相差一个或多个采样步，直接影响所有对齐图和首次异常时刻。

### 3.2 喷气前基准段应该取哪里？

B35 明确要求先计算喷气前基准段的平均值和波动范围，再计算喷气后相对基准的变化。当前还没有确定基准段时间窗口。

现在的疑问是：no-jet 和 `JET_01` 各自的喷气前基准段是哪一段？是否需要排除 case 开始后的初始过渡段？如果基准段取错，喷气后的相对变化会被初始漂移或未稳定状态污染。

### 3.3 喷气后比较窗口应该取哪里？

喷气后响应可能包含开启瞬态、准稳态段和后续漂移。不同窗口对应的平均变化、峰值变化和波动范围可能不同。

现在的疑问是：B35 应该用哪一段作为喷气后比较窗口？是否需要把喷气刚开启的瞬态和后续平均段分开？如果比较窗口不明确，就不能判断异常发生时刻和持续性。

### 3.4 两个 case 是否仍在漂移？

如果 no-jet 自身仍在漂移，`JET_01` 相对 no-jet 的变化不能只扣一个固定基准平均值。

现在的疑问是：no-jet 和 `JET_01` 在比较窗口内是否仍存在趋势性漂移？漂移幅度是否已经和喷气引起的变化同量级？如果仍在漂移，异常可能来自数值未稳定，而不是喷气本身。

### 3.5 6 区升力之和与 `Fz_Total` 是什么关系？

6 个区域力之和不一定等于整车总力。它们可能只覆盖局部表面，也可能与整车总力存在重叠或遗漏。

现在的疑问是：`Fz_S1L + Fz_S1R + Fz_S2L + Fz_S2R + Fz_S3L + Fz_S3R` 是否应该与 `Fz_Total` 近似一致？如果不一致，差异来自未覆盖表面、重复积分、方向不同，还是定义本来就不同？这个问题会影响区域异常和整车异常之间的关系判断。

当前已确认：6 个区域力和 `Fz` 在单位、坐标系、方向和力选项上一致，都是 `N`、`Laboratory`、`[0.0, 0.0, 1.0]`、压力+剪切。6 个区域力覆盖并互斥划分 `JET01..JET24` 底部边界；`Fz` 覆盖全部 `JET01..JET24` 并额外包含 `tail`。因此理论关系应理解为：`Fz_Total ≈ 六区底部力之和 + tail_Z`，而不是 6 区力之和直接等于整车升力。仍需确认 `tail` 的具体边界含义。

### 3.6 喷气面力是否被重复计入？

B35 需要区分车体气动力、喷气直接反作用力和合成有效力。但如果喷气面力已经包含在 `Fz_Total` 或某些区域力里，再额外加 `Jet_Reaction_Z` 就会重复计入。

现在的疑问是：`Fz_Total` 是否包含喷气边界？6 个区域力是否包含喷气面？`Jet_Reaction_Z` 和 `Fz_Total` 是否存在重叠积分表面？如果这些边界关系不清楚，有效总力的计算就可能反号、漏算或重复计算。

当前已确认：`Fz` 选中全部 `JET01..JET24` 底部边界和 `tail`，`Jet_Reaction_Z` 选中全部 `J01..J24` 喷气口，二者积分面不重叠。因此此前担心的 `Fz + Jet_Reaction_Z` 重复计入同一批 `JET` 底部边界的问题可以解除。仍需注意的是：6 个区域力已经覆盖 `JET01..JET24`，所以 6 区力与 `Fz` 的 `JET` 部分存在包含关系；`Fz` 还额外包含 `tail`。

### 3.7 有效总力应该如何理解？

B35 要区分车体气动力变化、喷气直接反作用力和两者合成后的有效变化。但在符号和积分面未确认前，有效总力的公式还不确定。

现在的疑问是：有效总力到底应该理解为 `Fz_Total + Jet_Reaction_Z`，还是 `Fz_Total - Jet_Reaction_Z`，或者只看某个已经包含喷气边界的总力？如果公式不清楚，“喷气是否改善升力”的判断可能完全相反。

当前已确认：`Fz` 与 `Jet_Reaction_Z` 的积分面不重叠，可以把 `Fz_Total + Jet_Reaction_Z` 作为当前 STAR report 覆盖表面的合计 +Z 力候选量。但这个候选量的准确名称应是“`JET01..JET24` 底部边界 + `tail` + `J01..J24` 喷气口壁面的 Laboratory +Z 压力+剪切力合计”，不是严格整车升力。是否把它作为 B35 的有效总力，还需要确认 `J01..J24` 改成质量流量入口后的力方向和质量流量正负号。

### 3.8 `actual_massflow_01` 的方向和大小是否正确？

`cmd_massflow_01 = 2.57 kg/s` 是动作表指令值，`actual_massflow_01` 才能证明 STAR 中实际发生的质量流量。当前在 STAR report/monitor 中没有找到 `actual_massflow_01` 或质量流量回读项；当前查看到的 `J01` 仍是 wall boundary。建模人已确认最终喷气建模方式是把 `J01` 改成质量流量入口。

现在的疑问是：最终质量流量入口如何绑定 `cmd_massflow_01=2.57 kg/s`，正值表示流入还是流出计算域，以及是否需要新增真实质量流量 monitor 来验证实际流量大小和方向。

### 3.9 喷气反作用力符号是否与质量流量方向一致？

喷气反作用力应该能和喷口法向、质量流量方向形成一致解释。但当前 `Jet_Reaction_Z` 的符号定义和 `actual_massflow_01` 的正负号关系还没确认。

现在的疑问是：当 `actual_massflow_01` 表示喷气开启时，`Jet_Reaction_Z` 应该变为正还是负？这个变化是否符合喷口法向和车体受力方向？如果不一致，可能是 report 定义反号，也可能是统计对象不是车体受力。

### 3.10 如果口径问题都排除，是否可能是真实流场响应？

B35 不能强行给出唯一原因，但需要区分数据定义问题、数值过程问题和可能的真实物理响应。

现在的疑问是：如果力方向、喷气面重复计入、`actual_massflow` 方向和大小、`Jet_Reaction_Z` 符号、checkpoint、数据窗口和漂移都不能解释异常，那么是否存在真实物理机制，例如喷气破坏原有高压区、增强泄漏、产生卷吸、改变底部流动分离或压力恢复？当前缺少流场证据，因此这类解释只能作为待判断的物理可能性。
